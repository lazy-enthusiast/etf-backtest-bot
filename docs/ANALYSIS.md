# 退休航道 — 讀法與改進（2026-11）

給個人使用的讀本。算法以 [METHODOLOGY.md](./METHODOLOGY.md) 為準；架構以 [CONTRACTS.md](./CONTRACTS.md) 為準。本檔回答三件事：它怎麼算、哪裡和一般回測器不同、下一步先改什麼。

這是歷史滾動壓力測試，不是報酬預測，也不是蒙地卡羅機率。畫面上的「成功率」是：歷史上每一個可當「今天」的月份各走一遍人生，其中撐到終點的占比。

---

## 1. 怎麼規劃、怎麼算

### 使用流程

1. 填退休計劃：現齡、退休年齡、終點年齡、現有資產、每月投入、年支出、其他收入、通膨、費用、提領規則。金額是**今日幣值**。預設幣別標籤是 HKD。
2. 填 ETF 組合。持倉必須寫 `TICKER.EX`（`VTI.US`、`VWRD.L`、`IGLN.L`、`2800.HK`）。權重會正規化成 100%。再平衡可選不調整、月、季、半年、年（預設年）。
3. 按重新計算。瀏覽器自己算，不把價格送到 AI。
4. 概況只放四個短數字：成功率、可花金額、提領率、所需報酬（名目），再加上最差起點一句話。點起始月可看該路徑的年表，也可匯出全部路徑 CSV。
5. 可選：打開「退休顧問」。AI 讀文字化的結果，可回傳 `portfolio`／`plan` 區塊。套用後寫回表單並重算。計算仍在瀏覽器。

### 資料從哪來

| 資料 | 來源 | 角色 |
|---|---|---|
| 一般 ETF／基金日線 | Worker `GET /api/series` → Yahoo 調整收盤；Cache API 約 24 小時 | 上市後的價格。日線窗口約 99 年 |
| 長歷史合成 | repo 的 `data/`：`US_STOCK_TR`、`US_10Y_TR`、`US_BILL_TR`、`GOLD_SPOT` | ETF 上市前往前接。月度，波動與回撤被平滑 |
| 通膨 | `CPI_US`（FRED CPIAUCNS；更早接 Shiller） | 把名目報酬折成實質。缺月改用計劃裡的固定年率 |
| 延伸規則 | `backtest/index-mapping.json` | 每個代號一串替代序列，依優先順序拼接，拼接點保留報酬率 |

`npm run fetch` 只更新合成序列與 CPI。新的一般 ETF 不必再把 JSON 放進 `data/`。

### 兩層計算

**組合回測**（`backtest/engine.js`，無 I/O）。各資產價格對齊到日期聯集，缺價用「該日或之前最後一筆」。再平衡日把權重扳回目標，預設不另計換手成本。產出名目淨值、CAGR、波動、最大回撤、相關、月度淨值。Sharpe／Sortino／Calmar 用 rf＝0，收在組合績效的進階裡。

**退休模擬**（`backtest/retirement.js`，無 I/O）。

- 實質月報酬＝名目成長 × 費用因子 ÷ 通膨因子 − 1。費用因子是 `(1 − feeRate/100)^(1/12)`，預設費用 0.2%/年。
- 現金流在月初：累積期加每月投入；到達其他收入年齡後加入；退休後扣提領。然後乘上該月實質報酬。餘額跌破 0 先歸零。
- 計劃從現齡走到終點，共 T 個月。歷史上每個夠長的起點各跑一次。歷史短於 T 就循環接回序列開頭，並標 `circular`。
- **可持續年支出**永遠用「固定實質、期末剛好歸零」來解，再取分位。護欄或 VPW 不會改這個定義。
- **SWR／PWR** 只看退休後那一段，與整段人生分開。SWR 是期末歸零的最大初始提領率；PWR 是期末保住實質本金的最大初始提領率。
- **所需報酬（名目）** 是另一個口徑：先解「累積到退休中位資產、再花到終點」所需的實質年化，再用計劃裡的 `inflationRate` 換成名目。它不改成功率。

### 提領規則

| 規則 | 行為 |
|---|---|
| `fixed_real`（預設） | 每年花固定的今日幣值。最能看出計劃脆不脆 |
| `guardrails` | 看**絕對**提領率（年提領 ÷ 當時資產）。高於 ceiling 就砍支出，低於 floor 就加支出。預設 6%／3%，每次調 10%，每 12 個退休月檢查一次。這不是「相對當初提領率 ±20%」的經典 Guyton-Klinger |
| `vpw` | 每月約等於餘額 ÷ 剩餘月數。幾乎不會歸零，熊市支出會下降 |

彈性規則會另外報一條固定實質對照成功率。看成功率上升時，要同時看支出覆蓋率。

### 預設關閉的模組

關閉時，舊的計劃 JSON 必須重現原來的成功率與可持續支出。`node --test backtest/*.test.js` 目前 46 項都在守這條（2026-11-03 本機跑過，46 pass）。打開之後的數字標成「估計」或「概念建議」，不用來取代關閉時的成功率。

包括：持倉上的股息稅負拖累（IE 15%、US 30%、其他默認 30% × 自填殖利率）、股債下滑、現金桶、支出曲線（75 歲後每年 −1%，或先降後升）、一次性支出、分段其他收入、歷史與區塊拔靴並列、費用拆成 TER／換手／匯率價差、支出匯率。港幣壓力行（可花金額 ×0.9、×0.8）只改顯示，不進模擬，並註明聯繫匯率 7.8。

### 刻意沒做

槓桿 ETF 的路徑依賴、遺產稅與完整稅務居民規則、模擬內部的匯率換算、香港 CPI、在 Worker 上重跑完整回測、搜尋權重或提領率來抬高成功率。

## 2. 哪裡不一樣

一般回測器給你一條淨值、一個 CAGR、一張最大回撤。這個工具把同一條歷史切成「如果人生從這一個月開始」的很多條路徑，專門看**報酬順序**（sequence of returns）：同樣的長期平均，退休前十年撞上差的年份，結果可以完全不同。

其他相對特別的地方：

- **今日幣值貫穿全程。** 支出與投入不逐年把名目金額調高；通膨從報酬裡扣掉。讀「一年花 30 萬」就是現在的購買力。
- **長歷史是拼出來的，而且會說自己在用什麼。** `VTI.US` 可接到 VTSMX、VFINX、再接到 1871 起的 Shiller 總報酬。`VWRD.L` 長樣本會掉回美股，mapping 註明「全球偏差」。`2800.HK` 只接到恒生**價格指數**，註明不含股息、港股殖利率高所以低估明顯。
- **代號規則是為香港常用市場寫的。** 美股、倫敦、港股後綴分開。不會把裸代號悄悄改成 `.L`。愛爾蘭註冊與美國註冊的股息預扣稅可以並排比較，這正是 VWRA／CSPX 對 VTI 的常見取捨。
- **成功率旁邊有樣本警告。** 起始月高度重疊。有效獨立樣本粗估是報酬月數／60；成功率剛好 100% 才加「資訊量有限」。有短缺就不加這句。
- **可選模組不準偷換基線。** 新數字站在舊數字旁邊。這對「我只是想看下滑路徑」很重要，避免前後兩次計劃無法對帳。
- **AI 是顧問，不是第二台引擎。** 對話走 Cloudflare Worker → Vercel Proxy → OpenRouter。預設 DeepSeek，Sonnet 要手動切。回測上下文約 12000 字。套用組合或計劃後前端重算，並把回執送回對話，減少模型自己否定上一輪代號。

## 3. 優先改進

下面按「會不會改到你拿來做決定的那個數字」排序。都還沒做；本檔只記錄判斷。

### P0 — 先處理會讓港元計劃失真的地方

1. **混合幣別沒有換算，警告卻不在概況上。** `engine.js` 直接把各序列的價格漲跌加權。`VTI.US` 是美元價，`2800.HK` 是港元價，加在一起不是一條港元報酬，也不是一條美元報酬。儀表板「資產明細」最底下有一句「各資產以自身幣別計算，未做匯率換算」，但預設分頁是概況的四個短數字，那句話不在那裡。  
   **做法：** 序列上已有 `currency` 欄。幣別不一致時，在概況成功率下面固定顯示這句，不要只放在資產明細。下一步再決定：美元資產先用聯繫匯率 7.8 折到 HKD（並標明這是聯繫假設），或其他幣別缺歷史匯率就拒絕出主成功率、只出警告。`fxMode` 是支出籃，預設關，不能拿來代替這一步。

2. **價格指數和總報酬拼在同一個組合裡。** `US_STOCK_TR` 含息；`^HSI`（盈富基金的延伸）不含息。港股歷史殖利率高，這條袖套的報酬被壓低，成功率會偏保守，而且和美股袖套的口徑不同。若再打開「股息稅拖累」，稅是從報酬裡另扣一筆假設殖利率；扣在已經不含息的序列上，等於股息先沒了、稅再扣一次。  
   **做法：** 結果裡列出「有多少權重、多少月份落在 `price_index`」。對這類月份，要嘛用一條寫明的總報酬假設補上股息，要嘛禁止同時套用稅負拖累。不要靜默改數字。

3. **實質購買力用的是美國 CPI。** 計劃幣別可以是 HKD，折現卻是 `CPI_US`。1970 年代和近年，香港與美國的通膨並不一致。概況上的「今日幣值」容易讀成香港的購買力。  
   **做法：** 概況註明「實質＝扣美國 CPI」。有餘力再加可選的香港 CPI，預設仍用現在這條，關掉時數字不變。

### P1 — 讓那個百分比更不容易被讀錯

4. **90% 以上會標成「穩健」。** 門檻在 `js/dashboard.js` 的 `successTone`。重疊的歷史起點很容易做出很高的百分比。方法論已經要求先看失敗年份是否扎堆，再看百分比。  
   **做法：** 概況保留百分比，把「穩健」改成中性詞，或只在「歷史與拔靴差距 ≤ 5 個百分點」時才用。失敗的 1 月起點（結果裡已有 `byStartYear`）做成一條年代刻度，讓 1966、2000 這類起點看得見。

5. **護欄的名字。** 程式常數寫著「護欄法（Guyton-Klinger）」，對話脈絡已經說明它是絕對提領率。表單若仍讓人聯想到經典 GK（相對初始提領率、通膨凍結），會和 Bogleheads 試算表對不上。  
   **做法：** 畫面上改成「絕對提領率護欄」，經典 GK 若要做，另開一個預設關閉的規則，不要覆蓋現在這條。

6. **全球股票的長歷史其實常常是美股。** `VWRD.L`／`VWRA.L` 在 VT 之前落到 `VTI`，再落到 `US_STOCK_TR`，mapping 寫了「缺國際」「全球偏差」。警告在資產明細，不在概況。  
   **做法：** 概況或組合摘要加一行：最長那段替代序列的名稱與類型。用全球配置做決定之前，先看到樣本是不是美國。

7. **給顧問的上下文，限制寫在後面。** `describeBacktest` 把「注意：…」放在最後。Worker 截到約 12000 字時，幣別、循環序列、價格指數這些話最容易被切掉。  
   **做法：** `backtestContext` 開頭固定三行以內：混合幣別、是否 circular、`price_index` 權重。不加大 token 預算。

### P2 — 工程與文件，不改公式

8. **測試沒有掛上日常指令，也沒有 CI。** 測試檔用 Node 內建 `node:test`，覆蓋「模組關閉時數字不變」、拔靴可重現、帳本對得上分位。`package.json` 沒有 `test` script，repo 裡也沒有 GitHub Actions。  
   **做法：** 加上 `"test": "node --test backtest/*.test.js"`，以及一條只跑這個指令的 workflow。

9. **`docs/WORK_LOG.md` 有過時句子。** 較早的條目仍寫 Block Bootstrap 與下滑路徑「尚未做」。本輪已在紀錄末段註明：它們後來做成預設關閉的可選項。以後改算法，先改 METHODOLOGY，再在 WORK_LOG 加一行，避免兩份文件各說各話。

10. **美國遺產稅只適合做提示，不適合做稅務引擎。** 香港一般沒有資本利得稅，這點工具沒有亂加稅，是對的。美註冊 ETF（`.US`）對非美國人仍可能涉及美國遺產稅；愛爾蘭 UCITS（`.L`）通常不計入美國遺產稅稅基。方法論把遺產稅列為刻意未做。  
    **做法：** 持倉裡有 `.US` 時，在進階或顧問脈絡放一句靜態提醒，不要把它算進成功率。

11. **區塊拔靴維持在歷史旁邊。** 它仍是從歷史區塊重抽，不是「假設每年平均 7%、波動 15%」的蒙地卡羅。若以後要加參數化蒙地卡羅，只能並列，並標成假設分配，不能取代歷史成功率。優先級低於 P0 的幣別與股息口徑。

12. **Sharpe 的 rf＝0、再平衡不計成本，維持現狀即可。** 兩者都已揭露，而且不在概況。真要動無風險利率或換手成本，走已經存在、預設關閉的費用拆分，不要改主數字。

### 建議的實作順序

先做 P0-1 的**顯示**（不改公式）：概況上看見混合幣別、美國 CPI、價格指數與循環序列。這一步不破壞「模組關閉時數字不變」。  
接著做 P0-1 的**換算**：只對 USD↔HKD 用標明的 7.8，其他幣別缺序列就不要出主成功率。  
然後做 P0-2 的口徑註記，避免恒生價格指數和美股總報酬被讀成同一種報酬。  
P1 的用詞、年代刻度、上下文開頭三行可以跟顯示一起做。  
P2 的 `npm test` 與 CI 獨立、範圍小，可以穿插。
