# 蒙地卡羅設計（尚未實作）

給 Sandy 決定做不做。這份只定口徑。本分支不改計算公式，只在 `simulateRetirement` 的 `successRate` 旁加了一句註解，避免之後把拔靴寫進主指標。

**歷史滾動的成功率維持主指標。** 新數字只能站在旁邊，不能寫進 `successRate`，不能拿去塗概況的圓環，也不能把兩個百分比平均成一個。

## 建議（先讀這段）

用**區塊重排**：把退休模擬已經在用的那條「實質月報酬」切成連續的塊，隨機接成與計劃一樣長的路徑，再用**同一套**月初現金流與提領規則走一遍。

不要用幾何布朗運動，也不要讓使用者填「預期報酬 7%、波動 15%」。那會把拼接過的歷史打扮成未來機率。

第一版預設**關閉**。打開之後，圓環仍是歷史起始月的占比。圓環下面另起一行，用下面的句子，不用「機率」「未來」「穩健」。

> 重排 61%（1,000 條，每塊 60 個月，種子 1）。把這段歷史打亂重接，不是未來機率。

幣別若混在一起（例如 `VTI.US` 與 `2800.HK`），這一行以「未換匯。」開頭。條數再多也不代表匯率被算過。

## 現在的拔靴為什麼不能直接當成這個功能

程式裡已有 `pathMode: 'bootstrap'` 與 `compareBootstrap`（`backtest/retirement.js`）。它們還不是這裡要的蒙地卡羅。

| 現況 | 問題 |
|---|---|
| `pathMode === 'bootstrap'` 時，`history.method` 變成 `bootstrap`，`successRate` 就是這次拔靴的占比 | 主指標被換掉。和「歷史成功率不能被取代」相反 |
| 路徑條數等於歷史起始月個數（歷史短於計劃時等於報酬月數） | 條數跟著重疊窗口走，不是獨立抽樣次數 |
| 一塊可以 `% L` 繞過序列頭尾 | 一塊裡面會把 2024 年接到 1871 年 |
| 歷史短於計劃時，`method` 只寫拔靴，循環這件事從方法名稱裡消失 | 短歷史被藏起來 |
| 並列結果差距 ≤ 5 個百分點會標「穩健」（`js/narrate.js`） | 容易讀成計劃很安全 |

這些開關維持現狀，本分支不改它們的數字。新功能用**另一個欄位**，不要擴充 `pathMode`。

## 路徑怎麼生成

抽的是已經扣過費用、折過通膨的那條組合實質月報酬（`realMonthlyReturns` 的輸出）。下滑若打開，股票袖與其他袖用**同一個月份索引**，不要各自亂抽。

一塊必須是歷史上連續的月份。起點只落在 `0 … L − 塊長`，**塊內不環繞**。塊與塊之間才相接。預設塊長 **60 個月**，讓 1973–74、2000–02、2008–09 這種連年差市留在同一塊。現有 `bootstrapBlock` 預設 12，是另一個開關，不要改它的預設，也不要兩套共用一個旋鈕。

每條路徑長度＝`(endAge − currentAge) × 12`，與今天的人生模擬相同。不另做一條只覆蓋退休後的蒙地卡羅；SWR／PWR 維持現在的歷史窗口算法。

條數固定 **1,000**，與歷史起始月個數無關。種子沿用現有的 `mulberry32`，畫面写出種子。同一種子兩次必須相同。換種子不是新的市場。

1,000 條、撐過比例約 80% 時，抽樣標準誤大約 1.3 個百分點。這只說明「這 1,000 次重排穩不穩」，不說明對未來有多準。不要畫成信心區間。

歷史短於 **10 年**，或短於兩塊：不算百分比，只寫「歷史太短，不報重排比例」。今天歷史不足會循環接回開頭（`circular`）；重排不是把同一條磁帶再播一圈，而是把短磁帶切塊重接。循環警告仍留在歷史結果上，不因為開了重排就拿掉。

## 什麼固定、什麼抽樣

**固定（沿用計劃，不重新抽）：** 年齡、本金、每月投入、年支出、其他收入、一次性支出、分段收入、提領規則與其參數（固定實質／絕對提領率護欄／VPW、檢查頻率）。費用與通膨已經在實質月報酬裡面，重排時不再抽一次，也沒有第二個通膨旋鈕。再平衡已做在組合月報酬裡，重排不再平衡一次。

**抽樣：** 只抽「下一個連續塊從歷史的哪一個月開始」。護欄狀態沿這條被打亂的路徑演變。這是報酬順序，不是新的平均報酬。

可持續支出仍用固定實質、期末歸零的定義。若使用者選的是護欄或 VPW，撐過比例跟所選規則走；可持續支出另用**同一組塊索引**再走一次固定實質。不要為支出分位重新抽一組路徑。這個分位寫在新欄位，不覆蓋現有的 `sustainableSpending`。

下滑、現金桶、支出曲線若已打開，重排跟歷史那一次用同一套。旁邊標「概念建議」的規矩不變。重排結果仍然不能寫回 `successRate`。

## 為什麼不是參數化或混合模型

參數化（各資產平均與共變異數、或 GBM）要先假設報酬來自一個穩定分配，再從估計出的平均與波動抽出未來。這份工具的月報酬是拼接的：合成月度會平滑波動，恒生延伸是不含息的價格指數，`VWRD.L` 的長段常常是美股，美元價與港元價還沒換算。在這條序列上估計平均與共變異數，小數點後面的精度是假的。

GBM 也不經過現在的月初現金流、護欄與 VPW。用期末公式會變成第二套引擎。

混合做法（區塊殘差再加上使用者填的漂移）是把預測塞進歷史。第一版不做「假設每年 7%」的入口。若以後要，必須叫「假設報酬」，單獨一欄，不能叫成功率，也不能與重排百分比平均。

各 ETF **不要分開抽**。分開抽會捏造 `VTI` 與 `2800` 的相關，看起來更分散，其實沒有共同的月份。

## 畫面上的數字與用詞

圓環、`successRate`、現有的可持續支出，都繼續是歷史起始月。重疊樣本那句話（月數／60）也留著。

打開重排後，圓環下方只加：

1. **撐過比例**：1,000 條裡，期末仍未耗盡的占比。句子必須同時寫條數、塊長、種子，並寫「把這段歷史打亂重接，不是未來機率」。
2. **耗盡年齡**：只在沒撐過的路徑上，給最早與中位。不把「沒有耗盡」算進中位。
3. **可持續年支出的 p10 與 p50**：固定實質口徑，標「重排路徑上的支出」，不取代歷史那一欄。

禁止：

- 把重排百分比叫機率、未來成功率、或信心。
- 兩個百分比差距小就標「穩健」。可以說「兩個口徑接近」。
- 用重排結果給圓環上色，或把兩個數合成一個。
- 用更多條數掩蓋短歷史、合成序列或未換匯。

給顧問的文字放在 `backtestContext` **開頭**三行以內（歷史占比、重排占比、未換匯／循環／價格指數）。不要只寫在末尾，以免 12,000 字截斷時先掉這句。不加大 token 預算。

## 幣別

重排吃的是歷史模擬同一條混合月報酬。`VTI.US` 加 `2800.HK` 時，這一條既不是港元報酬，也不是美元報酬。重排 1,000 次不會產生匯率。

規則：

- 序列上的 `currency` 不一致時，重排那一行以「未換匯。」開頭，並寫「與歷史成功率同一條價格」。後綴不能拿來猜幣別：`VWRD.L` 是美元。
- 幣別還不知道時，不假裝已換匯，句子用「未另做匯率」。
- 不要在重排裡抽美元兌港元的噪音，也不要把現有的 −10%／−20% 顯示壓力乘進重排路徑。那兩行仍只縮放畫面上的歷史可花金額。
- **參數化蒙地卡羅在單一計價幣出現之前不做。** 區塊重排可以先做，但不得比概況上的幣別警告更顯眼。圓環不能改成重排百分比。

## 建議的結果形狀（契約草案，尚未寫程式）

`successRate` 不變。關閉時沒有 `monteCarlo` 欄，舊 JSON 的成功率與可持續支出不變。

```text
monteCarlo: {
  label: "同一段歷史的區塊重排，不是未來機率",
  paths: 1000,
  blockMonths: 60,
  seed: 1,
  historyMonths: L,
  planMonths: T,
  suppressed: null,          // 或 "歷史太短，不報重排比例"
  solventRate: 0.61,         // 禁止複製到 successRate
  ruinAge: { min, p50 },     // 僅失敗路徑
  sustainableSpending: { p10, p50 },
  mixedCurrency: true | false | null,
  intraBlockWrap: false
}
```

實作時應抽出「塊索引」，再呼叫與 `walkLife` 相同的月初現金流規則，不要寫第二套提領公式。

## 不要做

- 用重排或任何蒙地卡羅取代、改寫歷史成功率。
- 把 `pathMode: 'bootstrap'` 的結果顯示成主指標。
- 參數化 GBM、自填預期報酬、各資產獨立抽樣。
- 把重排說成未來機率，或與歷史百分比平均。
- 在未換匯的組合上用更多路徑製造精度。
- 為了這個功能改費用因子、CPI、護欄或 VPW 的公式。
